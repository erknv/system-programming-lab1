## Сборка и запуск (Linux / WSL / GitHub Codespaces)

```sh
make                    # собрать create и remove
./create                # создать структуру программой на C
ls -liR Lab1_Erkinov    # проверить результат (или: tree Lab1_Erkinov)
./remove                # удалить структуру
sh create.sh            # создать ту же структуру скриптом
ls -liR Lab1_Erkinov

```

## Проверка результата

```sh
stat -c '%n: %s байт, inode=%i, ссылок=%h' \
  Lab1_Erkinov/docs/info.txt Lab1_Erkinov/backup/info_copy.txt \
  Lab1_Erkinov/data/random.bin Lab1_Erkinov/data/zeros.bin
```

Фактический вывод:

```text
Lab1_Erkinov/docs/info.txt: 33 байт, inode=803566, ссылок=2
Lab1_Erkinov/backup/info_copy.txt: 33 байт, inode=803566, ссылок=2
Lab1_Erkinov/data/random.bin: 1024 байт, inode=803569, ссылок=2
Lab1_Erkinov/data/zeros.bin: 256 байт, inode=803570, ссылок=1
```

- У `info.txt` и `info_copy.txt` один номер inode, счётчик ссылок равен 2, значит жёсткая ссылка работает.
- `cat Lab1_Erkinov/backup/todo_link` выводит содержимое `todo.txt`, значит символьная ссылка работает.
- `od -An -tx1 Lab1_Erkinov/data/zeros.bin | sort -u` показывает только `00`.
- После `./remove` команда `ls Lab1_Erkinov` выдаёт «No such file or directory».
- Повторный запуск `./create` при существующем каталоге даёт ошибку `mkdir: File exists`
  (защита от перезаписи).

## Контрольные вопросы

**Чем жёсткая ссылка отличается от символьной?**
Жёсткая ссылка — это ещё одна запись в каталоге, указывающая на тот же inode (данные общие).
Символьная ссылка — отдельный файл, внутри которого хранится путь к цели.

**Что будет, если удалить `docs/info.txt`?**
Данные останутся доступны через `backup/info_copy.txt`. Inode освобождается, только когда
счётчик жёстких ссылок становится равным 0.

**Что будет, если удалить каталог `docs`?**
`docs_link` и `todo_link` станут «висячими» ссылками: путь в них хранится, а объекта нет.

**Почему в `remove.c` символьная ссылка удаляется через `unlink`, а не обходится рекурсивно?**
Для ссылки `d_type == DT_LNK`. Если войти по ссылке `docs_link`, программа удалила бы
содержимое `docs` через ссылку, а при ссылке за пределы дерева — чужие файлы.

**Почему каталог удаляется последним?**
`rmdir` удаляет только пустой каталог, поэтому сначала удаляется всё его содержимое.

**Как `lseek` создаёт файл из нулей?**
Указатель переводится на позицию N-1 и записывается 1 нулевой байт. Пропущенная область
(«дыра» в файле) при чтении возвращает нули, итоговый размер равен N.

**Зачем `O_EXCL`?**
Вместе с `O_CREAT` он вызывает ошибку, если файл уже есть, поэтому существующие данные не затираются.
